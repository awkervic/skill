# Project Instructions (Gemini / Antigravity)

## 🌌 Neat Awker — 双轨制轻量化记忆与矩阵修剪协议

本项目已配置并启用 **Neat Awker** 技能。为解决长对话中整理记忆缓慢、消耗大量 Token 且容易导致反应迟钝的问题，必须严格遵循以下**“双轨制”轻量化协议**运行。

### ⚙️ 激活触发 (Triggers)
1. **【三合一】终极收尾**：当遇到长会话，或者用户输入 `“/neat-awker”`、`“整理对话”` 时，**必须强制运行三合一收尾总流**（包含逻辑蒸馏、双轨同步与物理大扫战场）。
2. **痕迹清理快捷触发**：当用户输入 `“/clean”`、`“清理缓存”` 时，仅触发物理删除 `Task Logs` 和运行垃圾。
3. **知识提炼快捷触发**：当用户输入 `“/distill”`、`“提炼思路”` 时，仅触发提炼核心逻辑并写入 `LOGIC_BASE.md`，随后物理清理。

### 🚨 与 think-same-skill 深度联动（核心开发红线）
1. **严禁直接编写/设计**：任何涉及代码编写、系统架构、配置逻辑或技术提案的任务，**严禁 AI 凭空臆想并直接输出成品**。必须百分之百自动触发并优先执行 `think-same-skill` 的 **【第一阶段：边界嗅探与反向提问】**！
2. **遵守交付四项红线**：开发过程必须始终受到 `think-same-skill` 的“硬核交付四项红线”（编码前思考、至简至上、精准手术、目标驱动）约束。
3. **规则基石对照**：开发时必须主动、首要地阅读由 `neat-awker` 维护的 `ai归档/核心规则/rules.md`，作为重要的避坑与决策参考。**注意：核心规则与逻辑思路是随着项目进展逐渐优化、动态演化的，绝非死守死律；一旦项目变动，必须随之动态调整与进化。**

### 🛠️ 【三合一】终极收尾运行指南 (Three-in-One Master Workflow)

收到 `/neat-awker` 或 `整理对话` 时，按顺序执行以下终极收尾流：

1. **第一阶段：深度蒸馏与知识存档**
   - 回顾本次会话的**具体做法**与**核心思路**，将其结构化写入项目根目录下的 `LOGIC_BASE.md`（若不存在则创建）。这些知识仅作为高价值的经验与思路参考系统，需随着项目进行而动态优化迭代，不可死记硬背。
   - 格式要求：`[日期] | [任务目标] | [核心方案] | [避坑指南/思路原因]`。

2. **第二阶段：双轨归档与规则修剪**
   - **轨一 (编年体记录 - 只写不读)**：将本次事件快照和总结追加到 `ai归档/编年体记忆/memory.md` 与 `Summarize.md` 末尾，严禁读取历史，节省 Token。
   - **轨二 (核心规则 - 洁癖修剪)**：读取 `ai归档/核心规则/rules.md`，使用变更影响矩阵同步路由、API和环境变量，**彻底清除所有过期/已完成的规则**，严格控制在 80 行内。

3. **第三阶段：物理打扫战场与清理**
   - **定位 UUID 会话路径**：在 `C:\Users\Dell\.gemini\antigravity-cli\brain\` 中定位当前会话的 UUID 文件夹。
   - **物理强力删除**：
     * 递归删除该 UUID 文件夹下的所有 `Task Logs` 和临时草稿。
     * 删除所有中间生成的 `scratch` 临时 Python 脚本。
     * 强制彻底删除当前工作区根目录下所有生成的 `__pycache__` 文件夹。
   - **安全红线**：绝对不能触碰任何用户手动创建的 `.py`、`.xlsx`、`.csv` 等数据资产。

4. **回复模板**：
   - 清理完毕后，简要列出已蒸馏写入 `LOGIC_BASE.md` 的“核心思路条目”。
   - 确认：*“冗长对话数据已清理，核心灵魂已锁死在 LOGIC_BASE.md。”*
   - 提示用户当前处于极致纯净状态，随时可以重置开启“零 Token 负担”的对话！
