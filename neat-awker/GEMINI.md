# Project Instructions (Gemini / Antigravity)

## 🌌 Neat Awker — 双轨制轻量化记忆与矩阵修剪协议

本项目已配置并启用 **Neat Awker** 技能。为解决长对话中整理记忆缓慢、消耗大量 Token 且容易导致反应迟钝的问题，必须严格遵循以下**“双轨制”轻量化协议**运行。

### ⚙️ 激活触发 (Triggers)
当遇到长会话，或者用户说：`“编年史”`、`“/neat-awker”`、`“整理记忆”`、`“收尾”`、`“整理文档”` 时，必须执行此收尾流。

### 🛠️ 双轨运行核心指令 (Twin-Track Execution)

1.  **轨一：编年体记录 (Chronicle - 只写不读)**
    *   **职责**：纯历史演进大事记与增量变动总结。
    *   **路径**：`ai归档/编年体记忆/memory.md` 和 `Summarize.md`。
    *   **动作**：**严禁读取这两个文件的历史内容**，直接增量追加本次会话的成果快照（北京时间 `[YYYY-MM-DD HH:mm]`）。**绝不**将其注入 Prompt 上下文中。

2.  **轨二：矩阵修剪与核心规则 (Matrix Pruning - 又读又改)**
    *   **职责**：实际指导 AI 编写代码的活动规则与边界。
    *   **路径**：`ai归档/核心规则/rules.md`。
    *   **动作**：主动读取该文件以指导当前操作。在整理时，应用**变更影响矩阵**同步最新的核心约束，同时**彻底删除**一切已过期、已稳定、已完成的临时规则，将行数**严格控制在 80 行以内**。

3.  **极速轻量化 (Speed First)**：
    *   只盘点本次会话的增量（Delta），不进行长篇大论的对话历史分析。
    *   归档所有的临时草稿、草稿文件至根目录的 `ai归档/` 文件夹，保持工作区清爽。

4.  **自动迁移与向后兼容 (Migration - 自动运行)**：
    *   每次整理前，自动检测并对齐旧版 `ai-neat-skill` 的遗留文件、目录名和文档内残留引用，将其批量重构替换为 `neat-awker`；已规整的内容直接忽略。
    *   旧版中包含的历史红线或硬规则，自动在首次运行时平滑提炼至新轨二的 `rules.md` 中。

详细协议与格式要求请严格参考 [SKILL.md](./SKILL.md)。
