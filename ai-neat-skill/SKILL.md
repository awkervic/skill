# 🌌 AI Neat Skill — AI 编年史记忆剪枝技能

## 📋 技能定义 (Skill Definition)

### 🎯 激活触发器 (Activation Triggers)
当满足以下任一条件时，必须启动该技能：
1. 用户输入关键字：`“编年史”`、`“/ai-neat-skill”`、`“整理记忆”`、`“同步到根目录”`、`“/sync-root”`。
2. 上下文长度接近 Token 限制 (80%+) 或 连续对话超过 20 轮。
3. 项目初始化或关键阶段结束，需要进行状态同步。

### ⚙️ 核心协议 (Core Protocol)
1. **禁止直接抹除**：严禁在未备份核心事件的情况下直接丢弃历史上下文。
2. **编年史压缩**：将琐碎的调试过程提炼为 [精确日期] 驱动的「核心事件快照」。
3. **归档与持久化 (Portability)**：在项目根目录 (Root) 下的 `ai归档/编年体记忆` 文件夹中生成并维护 `memory.md`。此文件是项目的唯一记忆源，确保项目迁移时记忆不丢失。
4. **增量总结 (Incremental Summary)**：在项目根目录下的 `ai归档/编年体记忆` 文件夹中维护 `Summarize.md`。每次对话产生变动后，必须以增量方式追加总结。
5. **记忆同步**：技能执行时需确保 `ai归档/编年体记忆/memory.md` 与计算机临时文件中的私有记忆 (Private Memory) 保持同步。
6. **临时文件归档**：在整理记忆/编年史压缩时，将整理过程中生成的所有临时文件、草稿、中间产物统一移动并整理到项目根目录下的 `ai归档` 文件夹中。

### 🛠️ 执行流程 (Workflow)

#### 第零步：环境准备 (Environment Setup)
- 确认项目根目录下是否存在 `ai归档/编年体记忆` 文件夹，若不存在则进行创建。
- 确认该文件夹下是否存在 `memory.md` 和 `Summarize.md`，若不存在则初始化。
- 确认项目根目录下是否存在 `ai归档` 文件夹，若不存在则进行创建。
- 检查 `memory.md` 尺寸：若超过 200 行，执行二次压缩。

#### 第一步：事件盘点 (Inventory)
识别高价值信息：架构决策、功能增量、关键修复、环境变更。

#### 第二步：提取快照与总结 (Extraction)
- **快照格式**：`[YYYY-MM-DD] <分类>：<事件描述> (指针/关联路径)`。
- **总结格式**：`### [YYYY-MM-DD HH:mm] (北京时间)` 紧跟变动描述。
- **时间规范**：必须使用北京时间 (UTC+8)，精确到分钟。

#### 第三步：同步与写入 (Sync & Write)
1. **更新 Root Memory**：将新快照追加至 `ai归档/编年体记忆/memory.md` 的分割线后。
2. **更新 Root Summary**：将本次变动的总结增量追加至 `ai归档/编年体记忆/Summarize.md`。
3. **同步私有记忆**：确保变更同步至当前会话的私有记忆空间。

#### 第四步：清理与归档 (Cleanup & Archive)
1. **临时文件归档**：将整理过程中产生的任何临时文件、草稿、中间备份等统一移动并整理到项目根目录下的 `ai归档` 文件夹中。
2. **清理冗余**：严禁在技能目录内保留冗余的 `memory.md` 等非技能定义文件。

- **Root/ai归档/编年体记忆/Summarize.md**：项目根目录归档文件夹下的增量变动总结。
- **Root/ai归档/**：项目根目录下用于存放临时整理文件与归档资产的文件夹。
